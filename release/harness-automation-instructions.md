# DSH 仓库自动化脚本规则

- 为完成用户任务而新建或修改脚本文件时，正式源码必须进入 `dsh-plugins` 仓库的独立任务 worktree；不要把 `~/.dsh/workspace`、OpenClaw workspace、`/tmp` 或容器内临时文件当成脚本的长期来源。
- 先按脚本承担的业务责任归类。业务归属明确时，放进 `automations/<对应业务名>/`；优先复用已有业务目录，新业务目录使用稳定、易懂的小写名称。
- 业务归属暂时无法明确时，放进 `automations/scripts/`。该目录不是业务脚本的大杂烩；一旦责任明确，应随正常开发任务迁到对应业务目录。
- `/opt/dsh/automations` 是已发布镜像中的只读运行副本，不是开发位置。不得修改运行中容器、在线补脚本或绕过 Git 发布边界。
- 写入前先读取仓库 `AGENTS.md`，确认任务分支基于最新 `main`；在独立分支完成实现和测试，并把脚本、必要测试及调用路径作为同一项正常开发改动提交。生产变更只通过仓库规定的 `release/dsh` 流程发布。
